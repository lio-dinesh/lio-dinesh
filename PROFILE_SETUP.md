## Interactive live dashboard

- Dashboard source: `dashboard/index.html`, `dashboard/styles.css`, `dashboard/app.js`.
- Live data feed: `dashboard/data.json`, generated by `scripts/generate-practice-streaks.mjs`.
- 3D renderer: Three.js 0.187.0 with OrbitControls; each scene is separate, with an independent canvas, camera, drag-to-orbit, scroll-to-zoom, hover inspection, reset and pause/resume rotation.
- **Monkeytype:** animated mechanical keyboard model. Keys pulse independently; hover a key or space bar to see typing activity and WPM/accuracy context.
- **LeetCode:** three difficulty towers for Easy, Medium and Hard. The towers rise with accepted-solution totals; their rings rotate independently.
- **CodeChef:** rotating trophy and podium with a small activity-bar field. Hover the trophy or a bar to inspect public profile and daily practice data.
- **GitHub:** a 91-day contribution cube field. Hover individual cubes to inspect contribution dates and counts.
- Visual palette: warm ivory `#F7F4ED`, soft charcoal `#34372F`, muted olive `#78816A`, soft terracotta `#C17A5B`, pale sage `#E4E7DA`, natural sand `#E5D8C6`. No neon-green theme.
- The dashboard checks `data.json` every 30 seconds in the browser. The Actions collector rebuilds source data every 5 minutes and deploys the Pages site on each successful run.
- Dashboard URL: https://lio-dinesh.github.io/lio-dinesh/.

### One-time GitHub Pages setting

1. Open https://github.com/lio-dinesh/lio-dinesh/settings/pages.
2. Under **Build and deployment → Source**, select **GitHub Actions**.
3. Open https://github.com/lio-dinesh/lio-dinesh/actions/workflows/practice-streaks.yml.
4. Click **Run workflow** on `main` to perform the first data refresh and Pages deployment.
5. When the deployment job succeeds, open https://lio-dinesh.github.io/lio-dinesh/.

### Live update behaviour

- The browser checks for a new JSON snapshot every 30 seconds while the dashboard is open.
- GitHub Actions fetches Monkeytype, LeetCode, CodeChef and GitHub data every 5 minutes and deploys the new dashboard snapshot if Pages is enabled.
- This is near-real-time polling, not an instant push from coding platforms. A platform must publish the test/submission first, then the next successful collector run can retrieve it.
- GitHub Actions can queue or delay scheduled events. External services can cache or rate-limit responses.
- The browser clock changes every second, but metrics change when a newer source snapshot is fetched.
- The dashboard requires browser WebGL support and network access to the pinned Three.js CDN. If 3D is unavailable, the stats and heatmaps remain readable.

## Near-real-time automation schedule

The live dashboard collector runs every 5 minutes, beginning at minute :02 to avoid the top of the hour. The animated contribution snake retains its separate 15-minute schedule.

| Workflow | Minutes (IST) | Refreshes |
|---|---|---|
| `Refresh live coding dashboard and deploy GitHub Pages` | `:02, :07, :12, :17, :22, :27, :32, :37, :42, :47, :52, :57` | Monkeytype, LeetCode, CodeChef and GitHub activity; 3D dashboard data feed and deployment |
| `Refresh GitHub contribution snake` | `:12, :27, :42, :57` | Contribution snake SVGs on the `output` branch |

Each workflow also supports manual dispatch from the Actions tab. The dashboard JSON feed and fallback SVG are committed only when their contents change, avoiding unnecessary commits when the upstream snapshot is identical.

### What 'near-real-time' means

- The live dashboard polls upstream services every 5 minutes; the contribution-snake workflow refreshes every 15 minutes. A new contribution or coding session should normally appear on the next successful poll, not instantly.
- GitHub Actions scheduled events can start late during high-load periods and GitHub does not guarantee exact execution at the cron minute. External providers can also cache or delay public profile data.
- GitHub does not expose one universal contribution-created webhook that can notify this profile repository for every contribution made in every other repository. Polling is therefore the practical cross-platform approach here.
- The activity calendar is rolling 91 days (13 weeks) and is rebuilt from the latest available source activity on each successful run.
- If you need an immediate refresh, use **Actions → the relevant workflow → Run workflow**.

### Data sources and limitations

- **Monkeytype:** current/max streak and public performance values are fetched from the public profile API. Detailed daily activity history may require public activity access or the optional `MONKEYTYPE_API_KEY` secret.
- **LeetCode:** the public GraphQL calendar and accepted-problem counts are polled. The upstream calendar may update after its own processing delay.
- **CodeChef:** the public heatmap, summary, profile and rating-history endpoints are polled. Heatmap-derived streaks may not include official streak-freeze days.
- **GitHub analytics:** GitHub GraphQL data is collected by the live dashboard workflow and stored in `dashboard/data.json` alongside Monkeytype, LeetCode and CodeChef.
- **Contribution snake:** the snake workflow regenerates its SVGs from the current GitHub contribution grid.

GitHub requires scheduled workflows to be on the default branch. The documented shortest schedule interval is five minutes; this repository uses 5-minute intervals to balance freshness, API usage and workflow queueing. Public-repository schedules may be disabled after 60 days without repository activity. See [GitHub workflow syntax](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#onschedule) and [schedule event guidance](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule).

## Important GitHub Actions setting

In repository **Settings → Actions → General → Workflow permissions**, allow **Read and write permissions** so the live dashboard workflow can commit refreshed data and SVG files. The Pages deployment also uses `pages: write` and `id-token: write` in the workflow.

## Troubleshooting

- **Live dashboard is not published:** enable GitHub Pages and set Source to **GitHub Actions**, then manually run the live dashboard workflow once.
- **Workflow cannot commit:** check Actions workflow permissions and ensure `contents: write` is allowed.
- **A platform panel is blank:** inspect the collector job log and that platform's public profile/API visibility.
- **Streak looks different from the GitHub UI:** GitHub determines contributions according to its published contribution rules and the profile's private-contribution setting.
- **Monkeytype or coding-platform card unavailable:** open the direct profile link; those cards are third-party images.

GitHub profile READMEs do not execute arbitrary JavaScript. These profile interactions use links, animated SVG assets, theme-aware `<picture>` elements and expandable Markdown/HTML sections.
